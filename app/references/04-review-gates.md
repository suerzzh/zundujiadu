# 04 — 审核门禁系统 (Review Gates System)

## 1. 核心目标
通过四遍修改法对剧本进行结构化多轮审查，确保每一轮聚焦不同维度，逐步提升剧本质量。

## 2. 四遍修改法 (Four-Pass Review Method)

### 第一遍：结构审查 (Structure Pass)
检查剧本的宏观结构是否合理：
- 每集是否有清晰的开场钩子、发展段落、转折点、结尾钩子
- 三幕式结构是否完整（setup → escalation → climax → resolution）
- 剧情节奏是否合理（不能连续3集无冲突升级）
- 集与集之间是否有逻辑衔接
- 事件流程是否完整，无断裂

### 第二遍：角色审查 (Character Pass)
检查角色相关的一致性和完整性：
- 角色行为是否与其性格设定一致
- 角色称呼是否前后统一（同一角色在不同场景中称呼一致）
- 角色关系发展是否有逻辑轨迹
- 是否有角色在多集中无任何发展（冗余角色）
- 主角是否在每集中都有主动性行为

### 第三遍：对话审查 (Dialogue Pass)
检查对话质量和规范：
- 每句对话是否不超过30字
- 对话是否推进了情节或揭示了角色
- 是否存在信息倾倒式对话
- 对话风格是否与角色性格匹配
- 对话与动作指示是否协调
- 是否存在无意义的填充对话

### 第四遍：细节审查 (Detail Pass)
检查细节层面的问题：
- 道具/线索在集间传递是否一致
- 时间线是否有矛盾
- 场景转换是否有逻辑连接
- 付费卡点位置是否合理
- 爽点兑现是否完整
- 伏笔是否有回收

## 3. 跨集重复检查 (Cross-Episode Duplicate Check)
- 检查不同集之间是否有重复的事件描述
- 检查不同集之间是否有重复的对话内容
- 检查不同集之间是否有重复的冲突模式
- 检查钩子是否重复使用

## 4. 事件完整性检查 (Event Integrity Check)
- 每个关键事件是否有明确的开始和结束
- 事件之间是否有因果逻辑关系
- 是否有未完成的事件线（开了头没收尾）
- 是否有事件在时间线上矛盾

## 5. PASS/FAIL 判定标准

### 通过条件
- 四遍审查中每遍的问题数 ≤ 3 个
- 无跨集重复问题
- 事件完整性 ≥ 90%
- 无角色行为矛盾

### 条件通过
- 四遍审查中每遍的问题数 3-5 个
- 发出修改建议，但不阻塞
- 作者可选择接受或忽略

### 不通过
- 四遍审查中任一维度问题数 > 5 个
- 存在跨集重复问题
- 事件完整性 < 80%
- 存在角色行为矛盾
- 建议重新生成相关集

## 6. 输出格式
审核结果以 JSON 格式输出，包含：
- 四遍审查结果（每遍的问题列表和建议）
- 跨集重复检查结果
- 事件完整性分数
- 质量门禁判定（PASS/FAIL/CONDITIONAL）
- 修改建议（带优先级）
